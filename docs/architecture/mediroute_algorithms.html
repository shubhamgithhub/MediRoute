3Evidence · LLM call 1LLM
Why
Pull out only the medical words, so the lookup is not misled by the rest.
Algorithm
  1. LLM copies conditions, procedures and body parts word for word (JSON schema, ≤ 6 per list)
  2. Code keeps a phrase only if ≥ 60% of its words are in the text (exact, abbreviation, or spelling similarity ≥ 0.85)
  3. Generic words and phrases with [PHONE]/[EMAIL]/[ID] are dropped
  4. Code adds everyday terms found word for word (keyword matches)
  5. Phrases for V1 = conditions + procedures + keyword matches (body parts only if nothing else)
Parameters / weights
prompt evidence_v1temperature 0, seed 7≈ 258 prompt tokens, 2–3 s
Example
in: fixed instruction + the message
LLM: {"conditions":["acid reflux","stomach pain"], "procedures":["endoscopy"], "body_parts":["stomach"]} check: all 4 kept (100% of words found) → V1 phrases: acid reflux · stomach pain · endoscopy
▼
4aV1 lookup voter · no LLMML search (code)
Why
An independent check against fixed medical data.
Algorithm
  1. Per phrase: remove generic words
  2. Keyword search: TF-IDF, 0.5 × word (1–2 words) + 0.5 × character (3–5 letters), cosine
  3. Meaning search: all-MiniLM-L6-v2 sentence embeddings, cosine
  4. Fuse by rank (Reciprocal Rank Fusion): score = Σ 1 / (60 + rank)
  5. Each phrase votes once: best entry's speciality full score, its other specialities × 0.1
  6. Sum over phrases; General Medicine dropped if any specialist matched
Parameters / weights
keyword min score 0.25meaning min score 0.45top 20 from each searchRRF k = 60top 8 entries per phraserunner-up weight × 0.1symptom / weak term × 0.5lookup: 10,884 entries (ICD-10-CM via AHRQ CCSR, CGHS, everyday terms)
Example
in: acid reflux · stomach pain · endoscopy
acid reflux → everyday term #1 in both searches (0.0328); K21 GERD (keyword #7, meaning #2) endoscopy → CGHS MG001 Upper GI endoscopy; ENT “endoscopy under GA” counted × 0.1 totals: Gastroenterology 0.0971 · Urology 0.0060 · ENT 0.0032 → V1: Gastroenterology

4bV2 AI voter · LLM call 2LLM
Why
An independent opinion from the whole message; never sees V1.
Algorithm
  1. LLM reads rules + every speciality (description, route here when, not here) + the message
  2. Must answer one name from the list or “Unclear” (JSON schema enum; code checks again)
  3. Up to 2 alternatives; cites the words that drove the choice
  4. Scores by rank 1.0 / 0.5 / 0.33: a choice, not a probability
Parameters / weights
prompt specialty_v2temperature 0, seed 7≈ 2,477 prompt tokens, 2–3 sruns at the same time as call 1 (hosted model)
Example
in: ≈ 10,000-character prompt + the message
{"specialty":"Gastroenterology", "alternatives":[], "evidence_terms":["acid reflux","stomach pain","endoscopy"]} → V2: Gastroenterology
▼
5Decide · first rule that matchesDeterministic code / rules
Why
Agreement of two independent voters is the main signal.
Algorithm
  1. V1 = V2 → that speciality
  2. Differ, and the patient's body-area answer fits exactly one → that one
  3. Differ otherwise → AI judge (5b)
  4. V2 “Unclear”, no phrases, or judge unsure → ask the patient
  5. AI unavailable → V1 alone, with a notice
  6. General Medicine on the first try → ask once more
Parameters / weights
—
Example
in: V1 Gastroenterology, V2 Gastroenterology
agreement → Gastroenterology

5bAI judge · LLM calls 3 + 4 (only if V1 ≠ V2)LLM
Why
Settles a disagreement without inventing anything.
Algorithm
  1. Closed choice: only the two candidates or “unclear”
  2. Must cite evidence lines built by code from the lookup; code checks they exist and support the choice
  3. Its quote must be in the patient's text
  4. Asked twice with the candidates swapped; both answers must match, else ask the patient

STEP 2 · speciality → ranked hospitals (no LLM)
1Eligible hospitalsDeterministic code / rules
Why
Only hospitals that offer the speciality, in the chosen area.
Algorithm
  1. Speciality must be in the hospital's list (own website = verified; team sheet = marked unverified)
  2. City or state filter from cities.csv
Parameters / weights
201 hospitals in hospitals.csv
Example
in: Gastroenterology · Mumbai
143 offer it · 12 in Mumbai
▼
2Similarity searchML search (code)
Why
Order eligible hospitals by how well their services match the request.
Algorithm
  1. Query text = speciality + diagnoses + procedures (+ findings)
  2. multi-qa-MiniLM-L6-cos-v1 embeddings; FAISS IndexFlatIP on normalised vectors = cosine
  3. Search only the eligible hospitals; take 3 × the number needed
Parameters / weights
top_k 5 → 15 candidates (12 available here)
Example
in: “Specialty: Gastroenterology. Diagnoses: acid reflux, stomach pain. Relevant procedures: endoscopy…”
semantic scores, e.g. Wockhardt Mumbai Central 0.385 · Hinduja 0.375 · Fortis Mulund 0.362
▼
3Transparent bonusesDeterministic code / rules
Why
Small, explainable extras; each one becomes a ranking reason.
Algorithm
  1. final score = semantic score + bonus
  2. bonus = min(0.2, sum of the parts)
Parameters / weights
website-confirmed speciality +0.04each matching procedure +0.04 (max 0.08)verified details +0.03 (partially +0.015)NABH +0.02 · JCI +0.02international patient services +0.02evidence quality up to +0.03 (High / Medium / Low)cap 0.2
